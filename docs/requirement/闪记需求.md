## 1. 本次重整结论

本次重整以“**现有页面已经成型**”为前提，核心结论如下：

1. 闪记不再表述为“全局模式切换页面中的一个选项”，而是产品内的**独立功能入口**（左侧导航“闪记”）。
2. 需求重点从“模式切换”转为“**闪记页面内的会话闭环**”：快捷键配置 → 开始会话 → 分片转写 → 会话查看/总结。
3. 系统默认处于“可一键转写”的常态；但闪记一旦开始，进入“闪记独占态”，其他核心录音功能（含一键转写）临时不可用，直到闪记结束。
4. 旧文档中与当前页面不一致的内容（例如强依赖 `voiceWorkMode` UI）降级为实现建议，不再作为 P0 必选交互。

## 2. 背景与目标

### 2.1 背景

VoiceKey 已有 PTT（一键转写）能力。当前业务新增“闪记”，用于长时记录场景（会议、访谈、灵感流）。

你提供的前端页面已体现出闪记的核心骨架：

- 左侧有独立“闪记”菜单入口。
- 页面内存在“闪记开始快捷键 / 闪记结束快捷键”的录制区。
- 页面主体存在“开始、结束、闪记 ID、总结、详情、分段列表”等会话展示结构。

### 2.2 目标

- **G1**：基于现有页面实现可用的闪记闭环，不推翻现有 UI 结构。
- **G2**：保障闪记开始键/结束键与其他快捷键不冲突。
- **G3**：默认状态保持现有 PTT 体验；当闪记进行中时，PTT 必须被临时禁用，闪记结束后自动恢复。
- **G4**：输出可直接拆解研发任务的需求（字段、状态、页面行为、异常路径）。
- **G5**：闪记数据在本地可追溯，使用 Electron 本地 SQLite 持久化会话、分片转写与会话总结。
- **G6**：遵循最佳开发实践（模块解耦、可测试、可回滚、错误可观测），确保迭代风险可控。

### 2.3 最终上线使用场景（关键）

1. 用户按一次“闪记开始快捷键”，系统进入持续录音。
2. 系统按 4 分钟自动切出一个录音分片（单片时长不得超过 5 分钟）。
3. 每个分片上传云端后，调用阿里云转写接口获取该分片文本。
4. 在闪记会话进行中，一键转写等其他核心录音能力不可触发（提示“闪记进行中，请先结束闪记”）。
5. 用户按“闪记结束快捷键”结束会话，系统完成最后分片处理。
6. 会话级与分片级数据落到本地 SQLite：
   - 会话：闪记 ID、开始时间、结束时间、会话总结。
   - 分片：分片时间范围、对应音频路径/标识、转写文本、处理状态。

## 3. 产品范围（按阶段）

### 3.1 P0（本期必做）

1. 闪记页面快捷键配置可用（开始/结束）。
2. 按开始键创建会话并持续录音，按结束键结束会话。
3. 会话按固定间隔切片并逐片上传/转写（4 分钟/片，且单片上限 5 分钟）。
4. 页面可查看当前会话与历史会话的片段明细。
5. 基础“总结”区域可展示（先支持手动触发或占位态）。
6. 使用 Electron 本地 SQLite 持久化会话与分片转写结果。

### 3.2 P1（增强）

1. 会话筛选/排序能力。
2. 失败片段重试入口（单片重试/整会话重试策略）。
3. 会话导出（文本导出或结构化导出）。

### 3.3 P2（二期）

1. 自动会话总结（LLM）。
2. 会话内关键结论提取（行动项/风险项）。

| 闪记会话（Session） | 用户按下“开始快捷键”到“结束快捷键”之间的一次完整记录 |

## 5. 页面与交互需求（以现有前端为准）

### 5.1 导航与入口

- 左侧导航保留独立入口：`闪记`。
- 点击后进入闪记页，页面包含两大区块：
  1. 快捷键配置区（开始键、结束键）。
  2. 会话内容区（会话元信息、总结、详情/片段）。

### 5.2 快捷键配置区（`HotkeyRecorder`）

- 必有两个录制项：
  - `闪记开始快捷键`
  - `闪记结束快捷键`
- 录制后即时展示组合键文本（例：`Ctrl+Shift+9` / `Ctrl+Shift+0`）。
- 校验规则：
  1. 开始键 ≠ 结束键。
  2. 两者都不能与现有全局快捷键冲突（至少包含 PTT、打开设置键）。
  3. 保存失败时要有明确错误提示，不可静默失败。
- 交互规则：
  1. 正在闪记时，不允许修改快捷键，按钮置灰并提示“请先结束当前闪记”。
  2. 未配置完整两键时，不可进入可录制态（提示引导用户先配置）。

### 5.3 会话主区（你当前页面结构对齐）

- 顶部元信息展示：
  - 开始时间
  - 结束时间（进行中为空）
  - 闪记 ID
- 中部“总结”区域：
  - P0：支持展示手动维护内容或空态文案。
  - P2：支持自动生成并回填。
- “详情”区域：
  - 逐片展示：片段序号、时间范围、转写内容、处理状态。
  - 至少支持以下状态：`录制中`、`上传中`、`转写中`、`成功`、`失败`。

### 5.4 闪记录音浮层（HUD）要求

1. 按下“闪记开始快捷键”并创建 `flashSessionId` 后，必须立即弹出录音状态浮层。
2. 浮层信息至少包含：`闪记进行中`、`已录制时长`、`当前状态`（录制中/处理中）。
3. 视觉和交互可复用现有一键转写浮层能力，但文案要区分为闪记语义。
4. 闪记结束并进入收尾后，浮层状态切换为处理中；处理完成后可隐藏或转为空闲态。

### 5.5 功能互斥规则（核心）

1. 系统日常默认可使用一键转写（PTT）。
2. 未开始闪记前，PTT 行为与当前版本一致。
3. 闪记开始后到闪记结束前，PTT 必须被阻断，不允许开启新的 PTT 录音。
4. PTT 被阻断时应给出轻提示（示例：`闪记进行中，请先结束闪记`），不可静默无响应。
5. 闪记结束并完成必要收尾后，PTT 自动恢复可用。

## 6. 核心业务流程

### 6.1 开始流程

1. 用户按开始快捷键。
2. 系统校验：两键已配置、无进行中会话、录音设备可用。
3. 创建 `flashSessionId`，会话状态置为 `recording`。
4. 标记系统进入“闪记独占态”，阻断 PTT 等其他核心录音入口。
5. 弹出闪记录音浮层并开始计时展示。
6. 启动录音分片计时器（固定 240 秒/片，单片不得超过 300 秒）。

### 6.2 分片流程

1. 到达分片时长后闭合当前音频片段。
2. 分片进入处理队列（上传云端 -> 阿里云转写）。
3. 新分片录音立即开始，保证长会话不断流。
4. 每片处理结果回写到会话详情。
5. 每片完成后立即写入 SQLite（分片元信息 + 转写文本 + 状态）。

### 6.3 结束流程

1. 用户按结束快捷键。
2. 停止继续生成新分片。
3. 当前最后分片闭合并入队。
4. 队列处理完成后，会话状态变为 `completed`。
5. 解除“闪记独占态”，恢复 PTT 可用。
6. 会话结束时间与会话总结写回 SQLite。

## 7. 数据模型（建议）

```ts
type FlashSessionStatus = 'recording' | 'flushing' | 'completed' | 'failed'
type FlashChunkStatus = 'pending' | 'uploading' | 'transcribing' | 'success' | 'failed'

interface FlashHotkeyConfig {
  flashStart: string
  flashEnd: string
}

interface FlashSession {
  sessionId: string
  startedAt: string
  endedAt?: string
  status: FlashSessionStatus
  summary?: string
  chunks: FlashChunk[]
}

interface FlashChunk {
  chunkId: string
  sessionId: string
  index: number
  startedAt: string
  endedAt: string
  audioPath?: string
  status: FlashChunkStatus
  transcript?: string
  errorMessage?: string
}
```

说明：是否需要 `voiceWorkMode` 字段由技术实现决定，不作为前端交互必选项。

### 7.1 SQLite 持久化（P0）

> 结论：闪记功能默认使用 Electron 本地 SQLite，不依赖远端数据库。

建议最小表结构如下（命名可按代码规范调整）：

```sql
CREATE TABLE IF NOT EXISTS flash_sessions (
  session_id TEXT PRIMARY KEY,
  started_at TEXT NOT NULL,
  ended_at TEXT,
  status TEXT NOT NULL,
  summary TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS flash_chunks (
  chunk_id TEXT PRIMARY KEY,
  session_id TEXT NOT NULL,
  chunk_index INTEGER NOT NULL,
  started_at TEXT NOT NULL,
  ended_at TEXT NOT NULL,
  audio_path TEXT,
  status TEXT NOT NULL,
  transcript TEXT,
  error_message TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  FOREIGN KEY (session_id) REFERENCES flash_sessions(session_id)
);
```

写入策略：

1. 会话开始时先插入 `flash_sessions`（`status=recording`）。
2. 每个分片创建时插入 `flash_chunks`，转写完成后更新 `transcript/status`。
3. 会话结束并全部分片处理后，更新 `flash_sessions.ended_at/status`。
4. 会话总结生成或编辑后，更新 `flash_sessions.summary`。

## 8. 验收标准（强制，按优先级）

1. **不影响现有一键转写（第一优先级）**：未开启闪记时，PTT 全链路行为与当前版本一致，不允许回归。
2. **闪记可闭环**：按开始后立即生成 `flashSessionId` 并进入录音；按结束后会话正确收尾。
3. **浮层可见**：闪记开始后必须弹出录音状态浮层，用户可看到录音时长和状态。
4. **分片策略达标**：按 4 分钟自动切片，且单片不超过 5 分钟。
5. **云转写可用**：每片音频可上传并调用阿里云转写接口，成功返回文本。
6. **本地可追溯**：会话信息与分片转写结果写入 SQLite，可按会话查询。
7. **工程质量**：实现遵循最佳开发实践（结构清晰、日志可观测、关键路径可测试）。

## 9. 异常与边界

1. **重复开始**：已有进行中会话时再次按开始键，给出“已在闪记中”提示并忽略。
2. **空闲结束**：无进行中会话时按结束键，给出轻提示并忽略。
3. **麦克风不可用**：开始失败，明确提示并停留空闲态。
4. **分片转写失败**：该片状态标记失败，允许后续重试，不影响其他片继续处理。
5. **应用重启恢复**：若检测到异常中断会话，进入 `failed` 或 `recovered` 处理策略（研发评审确定）。

## 10. 非功能要求

1. **可靠性**：分片失败不可静默丢失，必须可见。
2. **性能**：30 分钟以上闪记不出现明显卡顿或内存持续异常增长。
3. **可理解性**：页面文案以“开始/结束闪记”表达，不把用户暴露到技术术语。
4. **兼容性**：不破坏现有 PTT 功能链路和默认行为。
5. **本地数据安全**：SQLite 文件需位于应用数据目录，异常退出后数据可恢复读取。
6. **开发实践**：关键能力模块化（会话控制、分片调度、转写适配、数据持久化分层），便于测试与维护。

## 11. 与旧版需求相比的关键修订

1. 移除“用户必须先切换工作模式”的前台交互前提，改为“闪记独立入口 + 独立配置”。
2. 保留“录音链路互斥”作为后台实现约束，而非页面主心智。
3. 明确当前页面已包含的展示元素（会话 ID、总结、详情）是 P0 范围的一部分，而非后置能力。
4. 将“总结”拆成 P0 可展示 + P2 自动生成，避免一期目标过大。
